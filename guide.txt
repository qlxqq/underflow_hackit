KOPITALK - SETUP AND DEVELOPER GUIDE
=====================================

SETUP (first time)
-------------------
1. Clone the repo:
   git clone https://github.com/qlxqq/underflow_hackit.git

2. Move into the project folder:
   cd underflow_hackit

3. The website is plain HTML/CSS/JS with no build step and no npm
   packages. It connects straight to Supabase.

4. Open public/pages/auth/login.html in your browser, OR use VS Code's
   "Live Server" extension for auto-refresh while editing (recommended).

5. The Supabase URL and anon key are in public/js/shared/supabaseClient.js.
   They are safe to be public (access is controlled by Row Level
   Security).


FOLDER GUIDE
------------
public/
  pages/<name>/<name>.html   - one folder per page (login, profile, typing,
                               festival, storeVocab and so on)
  css/<name>/                - styles for that page
  css/shared/                - styles used by every page (base.css, topbar.css,
                               theme.css for dark mode)
  js/<name>/                 - scripts for that page
  js/shared/                 - code used by many pages (supabaseClient.js,
                               auth.js, streak.js, rewards.js, theme.js,
                               leaveGuard.js)
supabase/functions/<name>/   - edge functions (festival-verify, get-word-meaning)

Page naming rule: pages/typing/typing.html loads css/typing/typing.css and
js/typing/typing.js.


DARK MODE
---------
Every page should load these two lines in its <head>, after its own CSS:
   <link rel="stylesheet" href="../../css/shared/theme.css">
   <script src="../../js/shared/theme.js"></script>
theme.js sets data-theme="dark" or "light" on <html>. The dark colours for
each stylesheet live in css/shared/theme.css.


HOW TO ADD YOUR OWN FEATURE
----------------------------
1. Make pages/<feature>/<feature>.html, css/<feature>/ and js/<feature>/
2. Load the shared files you need (supabaseClient.js, auth.js) and the
   theme lines above
3. Add data changes as SQL and run them in the Supabase SQL Editor


DATABASE (Supabase)
--------------------
- Dashboard: https://supabase.com (log in, select the project)
- Change the schema by running SQL in the SQL Editor. Keep each change as a
  re-runnable .sql file in the repo so others can repeat it.
- After adding or changing a function, run: notify pgrst, 'reload schema';
- Row Level Security is ON. Users read only their own rows unless a
  policy says otherwise. Rewards are paid by database functions that run
  with the service role, not by the browser.


EDGE FUNCTIONS
--------------
- Deploy with: supabase functions deploy <name>
- Secrets (the AI API key and so on) are set in the Supabase dashboard or
  with: supabase secrets set NAME=value
- Never put a secret in the repository.


GIT WORKFLOW
------------
- main branch should always stay working - don't push broken code directly to it
- Create your own branch for your feature:
   git checkout -b feature/your-feature-name

- Push your branch:
   git push origin feature/your-feature-name

- Open a Pull Request on GitHub into main when your feature works

- Before starting work each session, pull the latest changes:
   git checkout main
   git pull origin main


DEPLOY
------
The site is hosted on Netlify (https://underflowhackit.netlify.app).
Pushing to main updates it.
